# 二、移动语义与值类别

核心判断：**这个对象在这里是左值还是右值、谁还需要它、转移之后源对象还能不能被读**。移动语义写错通常表现为「莫名其妙被掏空」或「性能不如预期（静默退回拷贝）」。

| 检查点 | 为什么要 | 反例 → 正例 | 标准 |
|---|---|---|---|
| 移动构造/移动赋值须标 `noexcept` | 否则 `vector` 扩容为保证异常安全会退回拷贝 | `Buffer(Buffer&&) { ... }` → `Buffer(Buffer&&) noexcept { ... }` | 11+ |
| 移动后置空源对象，且不再读源对象的旧值 | 源对象仍要析构；标准只保证「有效但未指定」状态 | 转移后补 `o.data_ = nullptr; o.size_ = 0;`，后续只用目标对象 | 11+ |
| 返回具名局部对象直接 `return v` | `return std::move(v)` 会阻止 NRVO，反而退化为一次移动 | `return std::move(v);` → `return v;` | 11+（C++17 起纯右值返回保证省略） |
| 泛型转发用 `std::forward<T>`，不要用 `std::move` | `move` 会把左值也右值化，`inner` 有移动重载时左值被掏空 | `inner(std::move(arg));` → `inner(std::forward<T>(arg));` | 11+ |
| 具名右值引用再传递前必须再 `move`/`forward` | 有名字就是左值，不会自动移动 | `void f(T&& r) { g(r); }` → `g(std::move(r));` | 11+ |
| 改实参用 `T&`，大对象只读用 `const T&`，小标量按值 | 按值传 `string`/`vector` 会深拷贝；`const&` 不拷贝且可绑临时量 | `void f(std::string);` → `void f(const std::string&);`（C++17 起优先 `std::string_view`） | 11+ |
| 禁止返回局部变量的引用/指针 | 悬垂引用即 UB；返回值交给 RVO | `int& bad() { int l = 1; return l; }` → 按值返回 | 11+ |
| 可空或需要换绑才用指针，否则优先引用 | 引用没有空状态、不可重绑，语义更安全 | 可空参数 `int*` → 若不可空则 `int&` | 11+ |
| 管资源的类按 Rule of Three 同写析构/拷贝构造/拷贝赋值，赋值先自赋值检查再释放旧资源 | 指针成员默认浅拷贝，析构双重释放 | 只写析构 → 补齐深拷贝构造与赋值，并加 `if (this != &other)` | 11+ |
| C++17 纯右值返回保证省略拷贝，不必为了省拷贝改成返回指针/引用 | 可返回不可拷贝、不可移动的对象 | `OnlyMovable make() { return OnlyMovable{}; }` | 17+ |
| 转移后若仍需使用源对象，要显式重建而不是依赖「有效但未指定」 | 标准不保证具体状态，跨标准库实现不可移植 | 移动后 `s = std::move(other);` 而不是假设 `s` 为空 | 11+ |
| 高频返回大对象优先靠 RVO/移动，而不是输出参数或堆分配 | 输出参数破坏可读性并引入更多间接层；堆分配更慢 | `void make(Big& out);` → `Big make();`（配合 C++17 保证省略） | 17+ |

**本参考未覆盖**：成员函数的 ref-qualifier（`&`/`&&` 限定）、异常安全等级与移动的取舍细节、C++20/23 关于移动的新特性。
